# sw.sword theme map

Purpose: save the navigator its first few searches. Theme → search words (EN / FR) → where to start in code.
**No behavior is described here** — read the code. Paths and anchors are checked by `tools/check_themes.py`; no line numbers.

Path aliases (the checker expands them): `sim/` = `src/libraries/simulation/` · `int/` = `data/app-data/resources/integration/` ·
`DEC/` = `src/libraries/simulation/Decision/` · other paths are relative to the sw.sword root unless prefixed `sw.models/`, `sw.soult/`, `directai/`.
`file::text` = an anchor: that text occurs in that file (or anywhere under that dir).
Physical XML lives in the model, e.g. `sw.models/data/data/models/ada/physical/mildb/` (ada is the standing model).
Model-side questions (which skill/task/mission/unit exists, wiring, which skill calls an `integration.*` function,
resources and action skills, ontology classes) belong to **sw-models-navigator** (kit `forge/docs/sw.models/`).
Generated indexes next to this file (grep, never read whole): `dec_function_index.md` (brain name → C++ registration),
`integration_index.md` (`integration.*` → definition, LDoc summary, brain calls, kernel starters, model callers, overrides).

## French vocabulary (grep both languages)
Pion = unit/agent · Automate = automat (unit group + CP) · Composante = equipment · Dotation = resource/supply item · Connaissance = knowledge ·
Embarquer / Débarquer = mount / dismount · Transporter = carry another unit · Foule / Population = crowd · Itinéraire = path · Tir = fire ·
Contourner = bypass · Valoriser = improve · Dévaloriser = demine/clear · Ravitaillement = resupply · Renfort = reinforcement · Rendu = surrendered ·
Brouillage = jamming · Silence radio = radio silence · Fuseau = AOR/zone · Lima = phase line · Mission impossible = `eRC_MissionImpossible` ·
Blessé = wounded · Mort = dead · Panne = breakdown · Carburant = fuel · Munition = ammo · Franchissement = crossing · Zone = area.

## Gotchas you would not think to grep for

Each line: the trap, then an anchor to start reading. Re-verify before quoting.

- **Entry point is one level above `integration/`**; the model loads it with `LoadResourcesFile( "Integration.lua" )`. `--integration-dir` points at the dir *containing* `Integration.lua`. → `data/app-data/resources/Integration.lua::include`, `DEC/DEC_Decision.cpp::LoadResourcesFile`
- **Models load after the layer and may override `integration.*`**, but code that cached a load-time local (`local f = integration.f`, `local _DEC_X = _DEC_X`) keeps the old value. A renamed C++ name gives a silent `nil` until first call. → `int/EquipmentIntegration.lua::local _DEC_`
- **A name defined twice in the layer: the file included last wins.** `integration.isFlying` is defined in `DestroyableIntegration.lua` (takes a knowledge `target`) and in `EquipmentIntegration.lua` (no argument, answers for `myself`), included later: `integration.isFlying( knowledge )` silently returns the caller's own state. Other duplicates: `integration_index.md` §3.1. → `int/EquipmentIntegration.lua::integration.isFlying = function()`, `data/app-data/resources/Integration.lua::include "integration/EquipmentIntegration.lua"`
- **All brains of one script share a Lua VM** (children of a cached archetype); globals leak across entities. → `DEC/DEC_Decision.cpp::archetype`
- **`_DEC__StopAction` returns 0, which is truthy in Lua.** → `DEC/DEC_ActionFunctions.cpp::StopAction`
- **The kernel does not cancel actions when a mission is replaced or a task stops**: `CancelAllActions` runs only on death, the `end_mission` magic action, deletion, brain reload or a pion Lua crash. Until then a started action keeps getting `Update()`; the model's Lua stop handlers are the only cleanup. → `sim/Entities/Orders/MIL_OrderManager_ABC.cpp::ReplaceMission`, `sim/Entities/Agents/MIL_AgentPion.cpp::CancelCurrentMission`, `sim/Entities/Agents/Roles/Decision/DEC_RolePion_Decision.cpp::EndCleanStateAfterCrash`
- **Kernel action starters are not recognisable by name**: they are the brain functions registered with `StartAction<` (`DEC_ChangeEquipmentActivation`, `_DEC_ReparerBlocUrbain`…), while `DEC_StartFragOrder` or `_DEC__StartOccuperObjet` are not actions. Stopping an equipment-activation action does not undo the change (applied once). The callback an action sends from its constructor is lost (`actionCallbacks[id]` is set after `_DEC_Start*` returns). → `DEC/DEC_ActionFunctions.cpp::DEC_ChangeEquipmentActivation`, `sim/Entities/Actions/PHY_ActionChangeEquipmentActivation.cpp::changeDone_`, `sim/Entities/Agents/Actions/Objects/PHY_ActionDestroyObject.cpp::GetInitialReturnCode`
- **No `integration.isLoaded`**: `self:isLoaded()` on model objects = transported by another unit. `agentIsMounted` and `agentIsDismounted` are both false mid-transition. → `sim/Entities/Agents/Actions/Loading/PHY_RoleAction_Loading.cpp::nState_ == eNothing`, `int/LoadableIntegration.lua::isBodyTransported`
- **Bug**: `DEC_Connaissances_Observable` uses `DEC_Knowledge_GetObjects` without `( myself )`. → `int/DECFunctionWrappers.lua::local objects = DEC_Knowledge_GetObjects`
- **`NIL` (MASA Life sentinel) ≠ `nil`**: check both for optional parameters. → `int/CommunicationIntegration.lua::NIL`
- **`Reports.lua` is generated** and absent from checkouts; every `eRC_` token in the layer (even in comments) is checked by `ant checkreports`. → `build/build.xml::checkreports`
- **Positions are committed in `UpdateEffects`**, after decisions: a unit entering sensor range in tick N is known to brains at N+1 at the earliest. → `sim/Entities/MIL_EntityManager.cpp::UpdateEffects();`, `sim/Entities/Effects/MIL_Effect_Move.cpp::Apply`
- **Unknown targets outside a sensor's `angle` are only checked on scan ticks** (every 12 ticks per unit, staggered, `scanning="true"` only). → `sim/Entities/Agents/Roles/Perception/PHY_RolePion_Perceiver.cpp::nNbrStepsBetweenPeriphericalVision`
- **A C++ exception inside a DEC call → `eRC_MissionImpossible`**, mission cancelled (pions: actions cancelled too). Pion-only functions called from an automat do this. → `sim/Entities/Agents/MIL_AgentPion.cpp::MissionImpossible`
- **Method forms `x:DEC_Agent_EstEnSilenceRadioEmission/Reception()` throw for every entity** (no override of the default), and `x:DEC_Agent_EstBrouille()` throws except on pions. Use the global forms with an agent argument. `integration.getRadioState` reads a decision-side variable, not the kernel's blackout flags. → `DEC/DEC_Decision.h::Invalid call of this Decision class`, `int/EquipmentIntegration.lua::F_Pion_GeteEtatRadio`
- **`integration.switchOffRadio( agent )` and the other switch helpers silence `myself`**; only the radio-state variable goes to `agent`. → `int/EquipmentIntegration.lua::_DEC_Agent_PasserEnSilenceRadio( myself )`
- **Mission parameters whose type has no Lua converter are silently not passed.** Missing Lua behaviors fail only at mission start. → `sim/Entities/Orders/MIL_ParameterType_ABC.cpp::MIL_ParameterType_ABC`
- **Frag orders must be polled** by pions/automats/crowds; only task groups get them pushed. → `DEC/DEC_MiscFunctions.cpp::_DEC_GetOrdersCategory`, `int/FragOrderIntegration.lua::GetOrdersCategory`
- **Second `RepertoireSources` for the same namespace is ignored** (`map::insert`). → `DEC/DEC_Workspace.cpp::RegisterSourcePath`
- **Checkpoints don't save the Lua VM**: only what `integration.savePersistentState` returns; missions restart on reload. → `int/SimulationIntegration.lua::savePersistentState`
- **Knowledge belongs to the knowledge group**; a unit re-seen after deletion gets a new id; object knowledge never decays (destroyed objects stay as ghosts until re-observed). → `sim/Knowledge/DEC_Knowledge_Object.cpp::DEC_Knowledge_Object`
- **Resource resupply is automatic in the kernel**: below a resource's `low-threshold` (% in Equipments.xml `composition` / Units.xml `logistics`), the company requests every resource below `high-threshold`. It is blocked if the logistic base is `supply-manual` or the unit is jammed; `integration.supplyRequest` only forces an early request. → `sim/Entities/Automates/MIL_DotationSupplyManager.cpp::IsSupplyManual`, `sim/Entities/Agents/Roles/Logistic/SupplyDotationRequestBuilder.cpp::NeedSupply`
- **Exercise setting `jam-and-blackout-dynamic-knowledge-groups` must exist** or the sim throws when it is queried. → `sim/MIL_AgentServer.cpp::jam-and-blackout-dynamic-knowledge-groups`
- **Speeds: km/h in XML, metres per tick inside**; hard-coded minimum speed. Equipment `speed-prototype` is decision-only; inline `<speeds>` moves units. → `sim/DefaultSpeedComputer.cpp::5.571`, `DEC/DEC_SpeedPrototypeContext.cpp::SpeedPrototype`
- **Percent vs ratio is inconsistent**: `hit-probability@percentage` is 0–1, protection breakdown/injury values are 0–100. → `sim/Entities/Agents/Units/Weapons/PHY_WeaponDataType_DirectFire.cpp::percentage`, `sim/Entities/Agents/Units/Categories/PHY_Protection.cpp::injured-percentage`
- **Integration Lua is deployed by copy** into `run/<platform>/resources`: after editing, `ant deploy-application-data` or run with `--integration-dir`. → `sim/Tools/MIL_Config.cpp::integration-dir`
- **Simtests fail on any Lua traceback in `Sim.log`** unless the test calls `DisableLuaChecks()`. → `src/masa/sword/simtests/::DisableLuaChecks`
- **`decisional.xml @model-version` must be ≤ the runtime major.minor**, or the sim refuses to start. → `DEC/DEC_Workspace.cpp::model-version`
