### Decisional entities (`decisional/dia5/`)
- Families (repertoires): `common`, `military`, `mildb`, `security`, `navy`, `crowd`, `test`. Plus `Decisional.lua`
  (only `include "FragOrder.lua"`), `FragOrder.lua`, `BMAgent.bms`, `_scripts/{Scripts,MessageTreatments}.lua`,

- Sub-tree layout is **not uniform** (`common/agent/behaviors/skills/actions` vs `military/agent/skills/actions`,
  `security/agent/Agent.xml` is a role outside `roles/`, `crowd/behaviors/ressources`). → classify by **root element**.
- Root element counts (1499 XML): skill 562, task 523, class 173, query 134, interface 36, role 32, resource 25,
  category 14 (`category-info.xml`, skip). All `xmlns="http://www.masagroup.net/directai/spark/lang/1.5"`.
- **Entity name = path under `dia5/` with `/`→`.` minus `.xml`**, verified for every entity except `category-info`. No duplicates.
- `.lua` sibling: skills 562/562, classes 173/173, queries 134/134, roles 14/32, **tasks 0/523**, interfaces/resources 0.
  Lua files without XML: only the 5 top-level files above.
- Regexes (on file text; root via first element after stripping `<?…?>` and comments):
  - root: `<([A-Za-z][\w.-]*)\b([^>]*)>` then `\bname="([^"]+)"` in its attributes
  - task → skill: `<behavior\s[^>]*?name="([^"]+)"` (832 refs; also in roles' `<default-task>`)
  - skill → skill: `<link\s[^>]*?target="([^"]+)"` (722; `name` attr = local link name used in Lua as `skill.links.<name>`)
  - → query: `<call\s[^>]*?query="([^"]+)"` (289; tasks' `<let>` and parameters)
  - role → skill: `<skill\s[^>]*?name="([^"]+)"` inside `<skills>` (22, with `<modifier>`s); role `<extends>`, `<body-type>`
  - skill → resource: `<resource\s[^>]*?name="([^"]+)"\s+variable=` inside `<resources>` (66)
  - types: `<object\s[^>]*?type="([^"]+)"` (3491), `<extends>`, `<implements>`
  - task metadata class: `<annotation key="spark.metadata-class"><entity>X</entity>` (134)
  - `<feedback name="…">`, `<stage label="…">` (→ Stages.xml, `checkstage`), `next-stage-when-done="true"`
  - All XML refs resolve except `sparkle.*` (directai built-ins: `sparkle.Object`, `sparkle.Task`,
    `sparkle.TaskMetadata`, `sparkle.deprecated.RoleBody`) and **2 case mismatches**: `mildb/agent/tasks/ByPassObjects.xml`
    and `BypassObstaclesWithinArea.xml` cite `mildb.agent.tasks.knowledge.BypassObjects` / `…BypassObstaclesWithinArea`
    but the classes are `…knowledge.ByPassObjects` / `…ByPassObstaclesWithinArea`. Effect unverified (ask dai-navigator).
    → the index should list unresolved refs with case-insensitive near-matches.
- Lua-side references (no XML):
  - queries are called as bare dotted names: `common.agent.queries.getX( { … } )`
  - tasks as string literals: `"common.agent.tasks.MoveAlong"` (e.g. `entitiesAndTasks[…] = { tasks = "…" }`,
    `sendDynamicMessage( "StartTask", …, { taskName = "…" } )`, `spark.getBehavior( "…" )`, `spark.stop( "…" )`)
  - commander skills pass unit task names as XML `<string>` parameter values, `;`-separated, in params
    `mainTask(s)`, `supportTask(s)`, `defaultTask`, `pcTasks`, … (list in `src/checkdec/tasks.go`)
  - → generic rule: any token `[a-z][A-Za-z0-9_]*(\.[A-Za-z0-9_]+){2,}` (quoted or not, also inside `;` lists) that
    equals a known entity name is a reference.
- Skill Lua: `rootnode{ … }` with `connections`, `create`, `activate`, `destroy`, link-feedback handlers (`done = …`),
  action skills add `acquire = { [ skill.resources.<variable> ] = 1 }`, `select`, `deselect`.
  `spark.action( rootnode )` in 6 files; `spark.startStopAction` 165 occurrences (phase C).
- `integration.*`: 948 distinct names called from 248 Lua files. Models **never call `DEC_*` directly** (0 hits;
  `build/checkdec.py` enforces it against `data/data/models/decfunctions.txt`, 1106 names). Only `FragOrder.lua`
  assigns `integration.*` (end of file: `integration.startFragOrderTask = fragOrder.startFragOrderTask`, …).
- Reports: 439 distinct `eRC_*` tokens in dia5 Lua → `physical/<db>/Reports.xml` `key=`; `ant checkreports`.
- Package matrix (`build/checkPackages.py`): common → none; crowd, military, security → common; mildb, navy → common +
  military; test → all. Governs where a new entity may go.

### Mission → task → skills
- `physical/<db>/physical.xml` names the files: `<missions file=…>`, `<models file=…>`, `<units file=…>`,
  `<automats file=…>`, `<populations file="Crowds.xml">`, `<stages file=…>`, `<reports file=…>`,
  `<units-mission-sheets-directory path=…>`. (sw.soult uses French file names; out of scope.)
- `Missions.xml` sections `<units>` (pion missions, `dia-behavior`), `<automats>` (`mrt-dia-behavior` +
  `cdt-dia-behavior`), `<populations>` (`dia-behavior`), `<task-groups>`, `<fragorders>` (`dia-type` only,
  `available-without-mission`). Each `<mission id name category dia-type>` + `<parameter dia-name name type optional is-context>`.
  ada/mildb: 372 `dia-behavior`, 99 frag orders. `dia-type` usually = task name but not always
  (e.g. `dia-type="agent.behaviors.t…"` on `PerformAWork`).
  - sw.sword reads `dia-behavior` to start the task (`DEC_RolePion_Decision.cpp`, automats: MRT then CDT phase in
    `DEC_AutomateDecision.cpp`), `dia-type` for the order type (`MIL_OrderType_ABC.cpp`, frag orders by dia-type).
- `Models.xml`: `<units>/<unit>`, `<automats>/<automat>`, `<crowd>/<crowd>`, `<task-groups>/<task-group>`, each
  `name`, `dia-type` (= **role** name, e.g. `military.agent.roles.Platoon`), `file="BMAgent.bms"`, `<missions>/<mission name>`
  each with `<fragorder name>` children, plus model-level `<fragorders>/<fragorder name>`. 94 unit + 54 automat models.
- `Units.xml` `<unit name decisional-model=… type>` (+ `<equipments><equipment type count crew major>`, sensors via
  equipments) → Models.xml unit `name`. `Automats.xml` `<automat name decisional-model>` with `<unit type min-occurs
  max-occurs command-post>`. Composition questions: grep these, never read whole (Equipments.xml 740 KB, Units.xml 255 KB).
- Mildb vs worldwide-tests differ (missions, Models.xml) → index per DB.
- Mission sheets: `physical/<db>/Mission sheets/{units,automata,crowds,task groups,fragmentary orders}/<mission name>.{xml,html}`
  (`checkdec sheets`). Translations: `physical/<db>/Locales/fr/<File>_fr.ts`, `<context><name>unit - <mission name>`
  (`checktranslations`, fix by loading/saving in SWORD Adaptation).

### Frag orders
- Kernel delivers to the model; `FragOrder.lua`: `fragOrdersToBePropagated` (list), `fragOrder.executeAutomatFragOrder`,
  `fragOrderTaskInitializers = { [ "<dia-type>" ] = function( mission, fragOrder ) … return true, "<task>" end }`,
  `fragOrder.startFragOrderTask`: no initializer → `integration.startFragOrder( myself, fragOrder.source )` (kernel);
  initializer returns `true[, newName]` → `spark.getBehavior( newName or dia-type ):start( mission )`.
  Client extensions add initializers via global `extensionsFragosInit`.
- Regex for the index: blocks `\[\s*"([^"]+)"\s*\]\s*=\s*function` up to the next such key; inside, `return\s+true\s*,\s*"([^"]+)"`.
