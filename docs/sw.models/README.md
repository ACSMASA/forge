# sw.models knowledge base (for the sw-models-navigator agent)

The navigator answers from the **files** of `C:/MASARepo/sw.models` (DIA5 decisional model and physical DBs). These files only save it searches:

| File | What | Maintenance |
|---|---|---|
| `THEMES.md` | vocabulary, theme → files map, non-obvious gotchas with `path::anchor` | hand-written, paths only, no line numbers; checked by `tools/check_themes.py` |
| `decisional_index.md` | every task, skill, query, role, resource (+ class/interface summary) with its wiring; missions, decisional models and frag orders per physical DB; unreferenced entities; unresolved references | generated by `tools/build_models_index.py`; header gives branch + commit |
| `ontology_index.md` | (phase B) classes, interfaces, roles: extends / implements / body-type, methods, callers, anomalies | generated |
| `action_index.md` | (phase C) action skills, resources, `startStopAction` methods, frameworks | generated |

Scope: sw.models only (model `ada` by default). sw.soult is not indexed.

After pulling sw.models or switching branches, from the forge root:

```sh
python -I tools/build_models_index.py C:/MASARepo/sw.models docs/sw.models            # all indexes, model ada
python -I tools/build_models_index.py C:/MASARepo/sw.models docs/sw.models --model mcast_v3   # a client model on its branch
python -I tools/check_themes.py sw.models   # exit 1 + list of stale paths/anchors in THEMES.md and the agent prompt
```

The generator reads the branch that is checked out. Commit regenerated indexes only when they were built from the
branch you want as the reference (normally the standing model's working branch); the agent falls back to grep when
the index commit differs from `HEAD`.

When the navigator returns **Map updates**, apply them to `THEMES.md` and re-run the checker.
