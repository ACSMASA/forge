# sw.models knowledge base (for the sw-models-navigator agent)

The navigator answers from the **files** of `C:/MASARepo/sw.models` (DIA5 decisional model and physical DBs). These files only save it searches:

| File | What | Maintenance |
|---|---|---|
| `THEMES.md` | vocabulary, theme → files map, non-obvious gotchas with `path::anchor` | hand-written, paths only, no line numbers; checked by `tools/check_themes.py` |
| `decisional_index.md` | every task, skill, query, role, resource (+ class/interface summary) with its wiring; missions, decisional models and frag orders per physical DB; unreferenced entities; unresolved references | generated by `tools/build_models_index.py`; header gives branch + commit |
| `ontology_index.md` | world classes (chain, interfaces, ontology keys, mission param types), every world-class method (form, override, callers by name: upper bounds), interfaces and implementers, task-metadata classes, roles (effective body type, type map), anomaly report | generated; header gives sw.models and sw.sword branch + commit |
| `action_index.md` | resources and the skills acquiring them; every action skill and every other skill with `<resources>` (pattern, callbacks, `startStopAction` methods called, integration calls, kernel action starters); every `spark.startStopAction` world method with its handlers; integration functions that start kernel actions; anomalies | generated; reads sw.sword integration Lua and the C++ `StartAction<` registrations; header gives both commits |

| `mission_index.md` | unit missions: §1 parameter-type catalog (Spark converter, absent value nil/NIL, ontology class, hashable, task shapes seen), §2 one row per mission per DB (task, params, models, end, stages, `mission_check` status), §3 skill signatures with persisted state keys and `checkpoint_lint` counts, §4 query signatures, §5 anomalies | generated (`--only missions`); reads sw.sword type tables; header gives both commits |
| `MISSIONS.md`, `CHECKPOINTS.md` | unit-mission anatomy and rules; save / resume hazards, conventions, sim-side gaps | hand-written, one-line anchored rules; checked by `tools/check_themes.py` |

Tools on the working tree (no index needed): `python -I tools/mission_check.py --mission "<name>"` (or `--task`,
`--all`) and `python -I tools/checkpoint_lint.py --skill <name>` (or `--task`, `--all`).

Scope: sw.models only (model `ada` by default). sw.soult is not indexed.

After pulling sw.models or switching branches, from the forge root: `python -I tools/kits.py` shows which indexes are
stale; `--build` rebuilds them (keeping the model recorded in their header) and runs the checker. One by one:

```sh
python -I tools/build_models_index.py C:/MASARepo/sw.models docs/sw.models            # all indexes, model ada
python -I tools/build_models_index.py C:/MASARepo/sw.models docs/sw.models --model mcast_v3   # a client model on its branch
python -I tools/build_models_index.py C:/MASARepo/sw.models docs/sw.models --only ontology    # one index (also reads --sword C:/MASARepo/sw.sword)
python -I tools/check_themes.py sw.models   # exit 1 + list of stale paths/anchors in THEMES.md and the agent prompt
python -I tools/check_themes.py --ref origin/USMC_June_2026 sw.models   # same, against another branch (no checkout)
```

In `--ref` mode, misses on lines marked `[branch-specific]` are warnings. A new miss on another line means: fix the
path or anchor so it holds on every branch, or mark the line.

The generator reads the branch that is checked out. Commit regenerated indexes only when they were built from the
branch you want as the reference (normally the standing model's working branch); the agent falls back to grep when
the index commit differs from `HEAD`.

When the navigator returns **Map updates**, apply them to `THEMES.md` and re-run the checker.
