# DirectAI / Spark theme map

Purpose: save the dai-navigator its first few searches. Theme → search words → where to start in code.
**No behavior is described here** — read the code. Paths and anchors are checked by `tools/check_themes.py`; no line numbers.

Path aliases (the checker expands them): `spark/` = `src/libraries/plugins/spark/` (Spark runtime, Lua) ·
`val/` = `src/libraries/spark/validation/` (validator, shared by the runtime and sparkcheck) · `core/` = `src/libraries/directai/` (libdirectai: brain engine, Lua VM).
Other paths are relative to the directai root unless prefixed `sw.sword/`, `sw.models/`, `sw.soult/`.
`file::text` = an anchor: that text occurs in that file (or anywhere under that dir).
Orientation (not evidence): `README.md` and `ARCHITECTURE.md` at the directai root (build, packaging, plugin loading, debug server); several of their claims are marked UNVERIFIED.

## Vocabulary (DAI term = what it means for a model)
Spark = the XML+Lua behavior language · sparkle / spark-core = the core library (`data/sparkle`, root category `sparkle`) ·
DIA / DirectIA / masalife = older names of DAI (`directia.*`, `masalife.*`, `sw.ai.*` survive as aliases) ·
entity = one XML file (role, skill, task, class, interface, query, resource) named by its path (`common.agent.behaviors.skills.Breach`) ·
root category = top directory of a library root, becomes a Lua global · behavior = skill or task · default task = a role's always-running task ·
node = a DAI graph node (a skill's `rootnode` or `node "name"`, a task, a task stage) · instance = one live copy of a node, keyed by its activation parameters ·
activation = `Activate` (one tick) / `StartActivate` (until `StopActivate`) · feedback = child → parent signal (`done`, `failed`, declared ones) ·
link = a skill's declared child behavior (`skill.links.x`) · resource = actuator, locked with `acquire` · modifier = per-role skill tunable ·
let-variable = task-local binding · body / `spark.body` / `spark.me` = the agent object / brain object (set by the role) ·
archetype brain = the root brain per brain file; agents are child brains sharing its Lua VM (sw.sword side) ·
`.bms` = Lua source with another extension (brain entry file; also accepted for skill implementations) · tick = `DeliverMessages` → `SelectActions` → `TriggerSelectedActions`.
Comments in core C++ are partly French (activité = activity, enregistrée = registered).

## Gotchas you would not think to grep for

Each line: the trap, then an anchor to start reading. Re-verify before quoting.

- **`sw.ai.*` and `masalife.brain.*` are alias tables over `spark.*`**, filled once at plugin load; some names differ (`sw.ai.stopTasks` = `spark.stopAll`, `sw.ai.setMessageTreatment` = `spark.setGlobalMessageListener`). Redefining `spark.X` later does not update the alias. → `spark/compatibility.lua::sw.ai = setmetatable`
- **Entity names are case-insensitive, and on a duplicate name across library roots the first root silently wins.** Library roots must not be nested. → `spark/library.lua::ignore entities having the same name in later root directories`, `spark/library.lua::distinct library paths have to be disjoint`
- **Each top directory of a library root becomes a shared Lua global** (`common`, `military`, `sparkle`…): a directory named like an existing global overwrites it for every agent. → `spark/library.lua::setsharedglobal( r, entity )`
- **`spark.createBrain` validates every entity in every root, used or not**; one invalid file anywhere aborts brain creation. Roles, tasks and Spark ≥ 1.4 skills are then loaded eagerly. → `spark/library.lua::if rep.bad then`, `spark/brain.lua::internal.library.loadEntity( descriptor.name )`
- **Strictness depends on `decisional.xml`**: found by walking up from the library root's *parent*; `model-version` < 6.7 makes strict errors (type mismatches, override errors) warnings at runtime. sparkcheck is always strict. → `spark/sword.lua::parent = parent:match`, `spark/library.lua::validation.setStrict( false )`, `src/applications/sparkcheck/reporter.lua::setStrict( true )`
- **sparkcheck runs skill/class Lua in a stub sandbox** (`.validation.lua` + 1 s timeout); a script that fails there is only a *warning* (`lua.run-error`, exit code still 0) **and skips all skill-Lua structural checks** (missing rootnode, unknown nodes…). sw.models' `.validation.lua` mocks `require` as a no-op. The real run (`dofile`, failures fatal) happens at brain load in the sim. → `val/api.lua::warning( "lua.run-error"`, `val/api.lua::createTimeoutHook( timeout or 1 )`, `val/validators/skill.lua::we silently skip all checks`, `spark/skill.lua::doFileAtParent( source )`
- **Nothing in validation checks that a skill's `.lua`/`.bms` exists**: sparkcheck only validates the script files it walks over; the sim fails with "cannot find Lua skill implementation file" (case-sensitive on Linux). → `spark/library.lua::local msg = "cannot find "`
- **A skill's implementation is looked up as `.lua` then `.bms`**: if both exist, `.lua` wins. → `spark/skill.lua::{ "lua", "bms" }`
- **`Activate` lasts one tick.** A child instance with no activation in a `SelectActions` is deselected, deactivated and destroyed in that pass; `StartActivate` persists until `StopActivate`. → `core/brain/Activation.cpp::rActivity_ = 0;`, `core/brain/Instance.cpp::CallDestructor`
- **Instance identity = node + hash of the activation parameters**: tables hash by deep content, functions by pointer, **userdata (sw.sword positions, etc.) by C++ object address**, `__daihash` overrides. A parameter whose value changes, a fresh closure, or a reallocated userdata creates a new instance (destroy + create) every tick. For example, a knowledge position is a new object at each change, while an agent's own position is updated in place. Passing the entity rather than its position avoids this. → `core/brain/tools/ParameterHashBuffer.h::case LUA_TUSERDATA`, `core/tools/binders/ScriptBinder.h::(void*)pValue_.get()`, `core/brain/VirtualMachine.cpp::Il y a une instance enregistree pour ces parametres`, `sw.sword/src/libraries/simulation/Knowledge/DEC_Knowledge_AgentDataDetection.cpp::position_.reset( new MT_Vector2D`
- **Nodes without `done`/`failed` handlers forward the child's `done`/`failed` as their own**; so a skill root ends when a linked child reports `done` unless it handles it. → `spark/skill.lua::constructor.done = constructor.done or forwardFeedbackDone`
- **A behavior's `done` stops it only if `disable-when-done`**; `failed` stops any non-default behavior. Listeners get `stopped` vs `interrupted` accordingly. Listener methods are called by exact name: `TaskStopped`/`TaskDone`… only work via `spark.registerTaskListener`; with `spark.addBehaviorListener` use `stopped`/`finished`. → `spark/behavior.lua::self:finish( self.behavior.disableWhenDone )`, `spark/behavior.lua::local TaskListenerAdapter`
- **`spark.start` only schedules**: the behavior runs from the next `SelectActions`; starting a running behavior restarts it as a new instance. `spark.stopAll()` spares the default task unless passed `true`. → `spark/behavior.lua::make sure activating behavior node will create a new node`, `spark/behavior.lua::includingDefaultTask`
- **Task stages: the first of `done`/`failed` received in a tick wins; `done` from the parallel stage is ignored unless the task disables when done.** → `spark/task.lua::the first feedback received`, `spark/task.lua::Ignore 'done' feedback from parallel stage`
- **Parameter checks are warnings, and only with type checking on** (sw.sword `--dec-typecheck`): missing, undeclared, wrong-typed, or `NIL` non-nullable parameters pass silently otherwise. Default values (including queries) are evaluated on every `Activate`. → `spark/parameters.lua::checkAndAddDefaultParameters`, `sw.sword/src/libraries/simulation/Tools/MIL_Config.cpp::dec-typecheck`
- **When candidates compete for resources, the highest activity wins**: activity = sum of activator activity × the `Activate` priority. The "selected boost" defaults to 1.0, so the current holder is **not** favoured unless the node declares `instances = { boost = x }`; with equal priorities (sw.models passes 1) the winner follows candidate insertion order (node depth via an unstable sort): treat ties as arbitrary. Instances beyond `instances.max` are suspended (deactivated, not destroyed). → `core/brain/Instance_ABC.h::GetActivity() > rhs.GetActivity()`, `core/brain/VirtualMachine.cpp::? 1.f : (float)lua_tonumber( pState, 3 )`, `core/brain/Node.cpp::suspension of remaining instances`
- **Resources are refilled every tick and only nodes with a `select` consume them**: `acquire` on an `activate`-only node does nothing. Capacity is 1 for any resource a skill declares unless a role `<resource initial-capacity>` or `spark.setResourceCapacity` changes it. A resource declared in the skill XML but never acquired gets no diagnostic. → `core/brain/Engine.cpp::ResetUsage();`, `core/brain/VirtualMachine.cpp::instance.SetSelectable(`, `spark/brain.lua::implicit default capacity`
- **`spark.action` generates the node's `select`/`deselect`**: `start` on the first `select` after each (re)selection, `started` on every `select`, `stop` = `deselect` (so losing the resource for a tick stops and later restarts it). Writing `select`/`deselect`/`activate`/`deactivate` yourself is `action.unexpected-field`; `Activate` inside `stop` is a runtime error. → `spark/integration.lua::in terms of "started()" and "start()"`, `val/validators/action.lua::action.unexpected-field`, `core/brain/VirtualMachine.cpp::Call to Activate not allowed in this function`
- **Destroying a brain calls no `deselect`/`destroy`**, so neither `spark.action` `stop` nor `startStopAction` `stop` runs (sim actions they started are not stopped by Lua). → `core/brain/Engine.cpp::Engine::~Engine()`, `spark/integration.lua::agentState[ uid() ] = nil`
- **Class rules (strict)**: a class `.lua` may define only methods declared in its **own** XML (even if the parent or an interface declares them) and must define every own non-abstract one; a concrete class must re-declare, non-abstract, in its own or an ancestor's XML, every method of its interfaces. → `val/validators/object.lua::class.lua.method.missing-declaration`, `val/validators/object.lua::local function checkAllMethodsImplemented`
- **A role's body type is checked statically only against its own `<skills>`**; skills reached through tasks and links are checked only at runtime with type checking on. → `val/validators/role.lua::checkSkillBodyTypeConstraints`
- **`spark.startStopAction` is keyed by (first arg `self`, action fn, content hash of the other args)**: `start` fires on *every* call in a tick where the key was not called the tick before (two callers on that tick → two `start`s, despite the doc comment), `started` on every call, `stop` once at the end of `TriggerSelectedActions` of the first tick without a call. Keys are weak: a collected `self` never gets `stop`. → `spark/integration.lua::functionsStartedLastTick[ executeFunction ][ paramsHash ] == nil`, `spark/BrainEventCallbacksHook.cpp::eTriggerActionsEnds`
- **`spark.send` deep-copies the content**: no functions; class instances need `__encode`/`__decode` or get their attributes copied. A message with no listener is dropped silently (logged only with type checking). → `spark/messaging.lua::only data can be sent in a message`, `spark/messaging.lua::ignored message`
- **"`spark.me` undefined" / "brain not created" are raised at the agent's first tick**, not at load. → `spark/core.lua::'spark.me' undefined`
- **Lua timeout comes from the session** (`lua-timeout`, default 30 s) and covers `SelectActions`, `TriggerSelectedActions` and script execution. → `sw.sword/src/libraries/simulation/Decision/DEC_Decision.h::SetTimeout( config.GetLuaTimeout() )`, `core/tools/LuaTimeoutHook.cpp::timeout_`
- **The debug HTTP server only starts when sw.sword's decisional debug port is > 0.** It has no auth, and DBGp connects *outward* to the IDE. → `sw.sword/src/libraries/simulation/Decision/DEC_Workspace.cpp::DebugServerStart`, `core/tools/debug.cpp::/dai/2.0/connect`
- **Which DAI a model actually runs is not the checkout**: sw.sword pins it in CMake/Docker, sw.models' sparkcheck takes the latest GitHub release, sw.soult's build may pin its own version; `directai/bin` holds git-ignored local drops. → `sw.sword/build/CMakeLists.txt::directai-${platform}-mt-`, `sw.models/build/build.xml::update-gh name="directai"`
- **Spark's checkpoint state is per task stage index, not per stage**: `seqStage` / `parStage` hold one table per behavior index, shared by every sequential stage, and a resumed task reruns its saved stage from `create`. Model-side hazards and conventions: forge `docs/sw.models/CHECKPOINTS.md`. → `spark/task.lua::local key = stage == task.parallel and "parStage" or "seqStage"`
