# DirectAI knowledge base (for the dai-navigator agent)

The navigator answers from **code**. These files only save it searches:

| File | What | Maintenance |
|---|---|---|
| `THEMES.md` | DAI vocabulary, theme → files map, non-obvious gotchas with `path::anchor` | hand-written, paths only, no line numbers; checked by `tools/check_themes.py` |
| `dai_lua_index.md` | `spark.*` API, `sw.ai.*`/`masalife.brain.*` aliases, shared globals → file:line + usage counts; validator diagnostic codes → message → raise sites | generated by `tools/build_dai_index.py` |

Scope: the Spark runtime and language. The SWORD kernel and its integration layer are covered by `docs/sw.sword/` and the sw-sword-navigator.
Out of scope in directai: `src/applications/ide` (Eclipse IDE), `src/applications/demo` (Unity), most of `data/tests`.

After pulling directai, sw.sword, sw.models or sw.soult (or switching branches), from the forge root:
`python -I tools/kits.py` shows which indexes are stale; `--build` rebuilds them and runs the checker. One by one:

```sh
python -I tools/build_dai_index.py C:/MASARepo/directai C:/MASARepo/sw.sword C:/MASARepo/sw.models C:/MASARepo/sw.soult docs/directai/dai_lua_index.md
python -I tools/check_themes.py directai   # or no argument: every kit
```

When the navigator returns **Map updates**, apply them to `THEMES.md` and re-run the checker.
